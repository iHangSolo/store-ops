## 新增需求

### 需求:门店客户端安装时生成唯一标识

门店客户端安装时必须生成唯一设备 ID 和设备指纹。

#### 场景:生成设备标识
- **当** 门店客户端首次安装运行
- **那么** 系统生成 UUID 作为设备 ID
- **那么** 系统采集设备指纹（CPU ID + 主板序列号 + MAC 地址 hash）
- **那么** 设备 ID 和指纹存储在本地 SQLite 数据库

### 需求:安装时输入门店名称

门店客户端安装时必须要求用户输入门店名称，便于总部识别。

#### 场景:输入门店名称
- **当** 门店客户端首次启动
- **那么** 显示输入框要求输入门店名称
- **当** 用户输入门店名称并确认
- **那么** 门店名称与设备 ID 一起发送到总部服务器

### 需求:首次连接需要审批

门店客户端首次连接总部服务器时，必须在后台显示为待审批状态。

#### 场景:首次连接
- **当** 门店客户端首次连接总部服务器
- **那么** 发送设备 ID、设备指纹、门店名称到服务器
- **那么** 服务器记录该主机为"待审批"状态
- **那么** 返回临时 TOKEN

#### 场景:总部审批通过
- **当** 总部署 IT 人员在后台审批该主机
- **那么** 主机状态变为"已激活"
- **那么** 服务器签发正式 TOKEN
- **那么** 门店客户端收到正式 TOKEN 并存储

#### 场景:总部审批拒绝
- **当** 总部 IT 人员拒绝该主机
- **那么** 主机状态变为"已拒绝"
- **那么** 门店客户端连接被断开

### 需求:TOKEN认证机制

门店客户端连接总部服务器必须使用 TOKEN 认证。

#### 场景:TOKEN认证
- **当** 门店客户端连接总部服务器
- **那么** 携带 TOKEN 进行认证
- **当** TOKEN 有效
- **那么** 连接建立成功
- **当** TOKEN 无效或过期
- **那么** 连接被拒绝

#### 场景:设备指纹校验
- **当** 门店客户端使用 TOKEN 认证
- **那么** 服务器校验设备指纹是否匹配
- **当** 设备指纹不匹配
- **那么** 认证失败（防止 TOKEN 被盗用）

### 需求:门店客户端开机自启

门店客户端必须支持开机自动启动。

#### 场景:开机自启动
- **当** Windows 系统启动
- **那么** 门店客户端自动启动并运行

### 需求:断线自动重连

门店客户端必须支持断线自动重连机制。

#### 场景:断线重连
- **当** 门店客户端与服务器连接断开
- **那么** 客户端自动尝试重连
- **那么** 重连间隔采用指数退避（1s/2s/4s/8s...最大 30s）

### 需求:心跳保活

门店客户端必须定期发送心跳保持连接。

#### 场景:心跳机制
- **当** 门店客户端连接正常
- **那么** 每 30 秒发送一次心跳
- **当** 服务器 3 次心跳未收到响应
- **那么** 判定客户端离线

### 需求:崩溃自动重启

门店客户端崩溃后必须自动重启。

#### 场景:崩溃重启
- **当** 门店客户端进程异常退出
- **那么** 系统自动重启客户端

### 需求:客户端界面显示连接状态

门店客户端界面必须显示当前连接状态。

#### 场景:显示连接状态
- **当** 门店客户端运行
- **那么** 界面显示当前连接状态（已连接/连接中/离线）
- **那么** 显示门店名称
